# 版权与合规红线

**这份文件不是可选的。** 违反下面的规则会让整个项目的可信度崩塌——
哪怕只有一条数据来自盗版源，整份合规声明就失去意义。

---

## 核心事实

考试主办方的官方材料（以 IELTS 为例，© IELTS Partners）：

- **仅限个人非商业使用**
- 明文禁止：商业用途、在他站再发布、修改、移除版权声明
- 相关名称是**注册商标**

因此本项目的立场是：**不碰真实考试材料，也不分发它们的解析产物。**

---

## 处置规则

| 对象 | 处置 |
|---|---|
| 官方 PDF / DOCX 原件 | 只落 `data/raw/`，被 `.gitignore` 排除，**永不提交、永不分發** |
| 官方评分标准原文 | 锁在 `rubrics/_official-reference/`，仅供人工对照，**禁止进 prompt、禁止入库** |
| prompt / rubric 里的评分标准 | **自述 paraphrase**：维度名 + 每档 3–5 条可观测特征，不逐字复制 |
| 官方题的解析产物 | 记 `redistributable: false`，元数据强制 `not_official: true` |
| 合成题的母本 | 只用 **CC-BY**（PLOS ONE / PMC OA / OpenStax 等）；Wikipedia（CC-BY-SA）可用但标 `redistributable: false` |
| 第三方代理抓取的题库 | **仅本地缓存，绝不入库、绝不分發** |
| 随仓示例数据 | 凭空撰写的合成内容，无版权负担 |
| 数据包（`packs/`） | **不入库**。每个包自带 `pack.json` 声明许可与 `redistributable`，由提供方负责 |

## 为什么"官方免费样题"也不能入库

一个常见的误解是："官网免费下载的样题，我拿来做数据集应该没问题。"

**不行。** 免费下载 ≠ 允许再分发。主办方的表述是"仅限个人非商业使用"。

但**用它们验证解析链路是可以的**，而且我们推荐这么做：

- 官方免费样题与真题由同一批出题方制作，**版式与真题高度一致**
- 用它验证解析器的判别力，等价于用真题验证
- 零版权风险，且解析产物仍可留作本地使用（只是不能公开分发）

## 产品层面的要求

如果你的项目基于 SKILL 构建并对外提供服务：

1. **产品命名不得包含考试主办方的商标**（如 `IELTS`）。
2. **UI 必须展示"AI 估分，非官方成绩"**。
3. 任何分数展示都要标注为**参考区间**，不能伪装成官方成绩。

第 3 条不只是合规问题——见
[known-limitations.md](known-limitations.md#L3-写作评分没有可信真值--最重要的一条)：
我们在技术上也没有能力给出可信的确定分数。

## 自检清单

提交或发布前，逐条确认：

- [ ] `git status` 里没有任何 `data/raw/` 下的文件
- [ ] 没有用 `git add -f` 强行加入被忽略的文件
- [ ] `rubrics/` 与 `prompts/` 里没有官方评分标准的原文
- [ ] 所有结构化产物带 `not_official: true` 与 `redistributable` 字段
- [ ] `examples/` 下没有真实题目
- [ ] `packs/` 没有被提交（除 `examples/packs/` 的格式示范包）
- [ ] 每个数据包都在 `pack.json` 里如实声明了 `licence` 与 `redistributable`
- [ ] 产品 UI 有"AI 估分，非官方成绩"的标注

可以跑一遍自动化检查：

```bash
git ls-files | grep -E "^data/raw/|^data/structured/" && echo "✗ 有数据文件被追踪" || echo "✓ 数据目录干净"
```
